أريد تطوير الموقع بإضافة **نظام أخبار متكامل وحديث** مع إنشاء **لوحة تحكم إدارية خاصة بالموقع** لإدارة الأخبار والمحتوى بسهولة، وربط النظام بالكامل مع **Supabase** ليكون مسؤولًا عن قاعدة البيانات والتخزين وتسجيل الدخول.

**مهم جدًا:** قبل إجراء أي تعديل، افحص المشروع الحالي بالكامل وافهم بنيته وتقنياته. لا تحذف أو تعطل أي ميزة موجودة، ولا تعيد بناء المشروع من الصفر. أريد إضافة النظام إلى المشروع الحالي بطريقة منظمة ومتوافقة معه ومع Vercel.

---

# 1. ربط المشروع بـ Supabase

اربط المشروع الحالي بـ **Supabase** واستخدمه كخدمة Backend للنظام الجديد.

استخدم:

* **Supabase Database** لحفظ الأخبار والملاحظات والبيانات.
* **Supabase Storage** لتخزين الصور والفيديوهات.
* **Supabase Authentication** لتسجيل دخول مسؤولي لوحة التحكم.
* **Row Level Security (RLS)** لحماية البيانات ومنع الوصول غير المصرح به.

أنشئ الجداول والعلاقات المطلوبة بشكل منظم.

### جدول الأخبار

أنشئ جدولًا مناسبًا للأخبار يحتوي على الأقل على:

* id
* title
* slug
* short_description
* content
* category
* main_image
* status
* published_at
* created_at
* updated_at
* author_id

### جدول الملاحظات

أنشئ جدولًا للملاحظات الإدارية يحتوي على:

* id
* title
* content
* priority
* status
* is_pinned
* created_at
* updated_at
* author_id

### الوسائط

نظّم تخزين الصور والفيديوهات في Supabase Storage بطريقة مناسبة، مع إمكانية ربط كل ملف بالخبر الخاص به.

---

# 2. نافذة الأخبار في الموقع

أنشئ صفحة/قسم احترافي باسم:

**"آخر الأخبار"**

يظهر للزوار بشكل واضح وجذاب.

كل بطاقة خبر يجب أن تحتوي على:

* الصورة الرئيسية.
* عنوان الخبر.
* وصف مختصر.
* تاريخ ووقت النشر.
* تصنيف الخبر.
* زر **"اقرأ المزيد"**.
* تصميم متجاوب مع الهاتف والتابلت والكمبيوتر.
* دعم RTL للغة العربية.
* حركات انتقالية بسيطة واحترافية إذا كانت مناسبة للمشروع.

عند فتح الخبر، تظهر صفحة التفاصيل وتحتوي على:

* عنوان الخبر.
* الصورة الرئيسية.
* محتوى الخبر.
* معرض الصور.
* الفيديو إن وجد.
* تاريخ النشر.
* التصنيف.
* أخبار ذات صلة.

الأخبار المنشورة فقط هي التي تظهر للزوار.

# 3. لوحة التحكم Admin Dashboard

أنشئ **لوحة تحكم إدارية منفصلة** لا تظهر للزوار العاديين.

يتم الدخول إليها من خلال Supabase Authentication.

يجب أن تحتوي لوحة التحكم على:

### إدارة الأخبار

* إضافة خبر جديد.
* تعديل الخبر.
* حذف الخبر.
* حفظ الخبر كمسودة.
* نشر الخبر.
* إلغاء نشر الخبر.
* تحديد تاريخ النشر.
* إضافة العنوان.
* إضافة وصف مختصر.
* كتابة محتوى الخبر.
* اختيار تصنيف.
* إضافة صورة رئيسية.
* رفع عدة صور.
* رفع فيديو.
* معاينة الخبر قبل النشر.

---

# 4. رفع الصور والفيديوهات

اجعل عملية رفع الملفات **Mobile First** ومناسبة جدًا للهاتف.

يجب أن يستطيع المدير:

* اختيار الصور من الهاتف.
* اختيار الفيديوهات من الهاتف.
* رفع عدة صور في نفس الوقت.
* معاينة الملفات قبل الحفظ.
* حذف الملفات قبل النشر.
* تحديد الصورة الرئيسية.
* إظهار تقدم عملية الرفع.
* التعامل مع أخطاء الرفع برسائل واضحة.

يجب أن يتم رفع الملفات مباشرة إلى **Supabase Storage**.

لا تعتمد على إدخال روابط الصور أو الفيديوهات فقط.

**"الملاحظات المهمة"**

# 7. نظام تسجيل الدخول والصلاحيات

استخدم **Supabase Authentication**.

أنشئ نظام صلاحيات مناسب بحيث:

### الزائر:

* يستطيع مشاهدة الأخبار المنشورة فقط.
* لا يستطيع الوصول إلى لوحة التحكم.

### المدير:

* يستطيع تسجيل الدخول.
* إضافة الأخبار.
* تعديل الأخبار.
* حذف الأخبار.
* نشر وإلغاء نشر الأخبار.
* رفع الصور والفيديوهات.
* إدارة الملاحظات.

استخدم **Supabase RLS Policies** لحماية البيانات.

لا تضع أي Secret Keys داخل Frontend.

استخدم Environment Variables مثل:

NEXT_PUBLIC_SUPABASE_URL

NEXT_PUBLIC_SUPABASE_ANON_KEY

وأي مفاتيح سرية أخرى يجب أن تبقى في بيئة الخادم فقط.

# 9. الحفاظ على المشروع الحالي

هذه نقطة مهمة جدًا:

**لا تحذف أي شيء من المشروع الحالي.**

قبل التعديل:

1. افحص جميع الملفات.
2. افحص package.json.
3. حدد Framework المستخدم.
4. حدد نظام Routing المستخدم.
5. افحص طريقة التعامل الحالية مع البيانات.
6. افحص Environment Variables.
7. افحص أي Backend موجود.
8. افحص المشروع للتأكد من توافقه مع Vercel.

بعد ذلك قم بإضافة Supabase والنظام الجديد بطريقة متوافقة مع البنية الحالية.

إذا كان هناك نظام Backend أو قاعدة بيانات موجودة بالفعل، لا تحذفه مباشرة؛ حدد أولًا أفضل طريقة لدمج Supabase معه.

# 10. توافق Vercel

يجب أن يكون المشروع متوافقًا بالكامل مع **Vercel**.

بعد الانتهاء:

* شغّل npm run build.
* أصلح جميع أخطاء Build.
* أصلح أخطاء TypeScript.
* أصلح أخطاء ESLint إن كانت تمنع Build.
* تأكد من صحة Environment Variables.
* تأكد من أن Supabase يعمل في بيئة الإنتاج.
* تأكد من أن رفع الصور والفيديوهات يعمل بعد النشر.
* تأكد من أن تسجيل الدخول يعمل على Vercel.
* تأكد من أن الأخبار تظهر بشكل صحيح للزوار.
